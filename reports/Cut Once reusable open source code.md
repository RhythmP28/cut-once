# Borrow Meta's code, fix ours first

Almost every piece of Cut Once we still have to build already exists as readable, mostly permissively licensed code, and much of it is already in our QuestCameraKit fork or in Meta's own packages. The biggest time-savers come from calling Meta's functions instead of re-deriving the maths. `PassthroughCameraAccess.WorldToViewportPoint` and `GetCameraPose()` do the camera projection for us ([MRUK source](https://github.com/darktable-mirror/com.meta.xr.mrutilitykit/blob/v205.0.0/Core/Scripts/PassthroughCameraAccess.cs#L539-L590)). Meta's MIT-licensed StarterSamples show the full save/load/localise/bind cycle for spatial anchors ([SpatialAnchorLoader.cs](https://github.com/oculus-samples/Unity-StarterSamples/blob/main/Assets/StarterSamples/Usage/SpatialAnchor/Scripts/SpatialAnchorLoader.cs)). The fork's own MIT scripts already record the mic, write WAV files, call a server and wire a controller-ray UI. Around those sit small, liftable pieces: zalo's public-domain Kabsch solver, HoloLab's MIT outlier filter, RageAgainstThePixel's MIT streaming-audio pattern, openai-node v7, the ElevenLabs JS SDK, `sharp` for drawing numbered boxes on photos, Microsoft's SIGMA prompt layout, the OpenAI Cookbook's image grader, and Elastic's own notebooks and workflow examples. The more urgent finding is what the comparison turned up in code we have already written. Our Agent Builder tools will be rejected with HTTP 400 on a 9.4 cluster. The `log_issue` path can log the same issue twice. The Workflow's headers are templated wrongly. The MCP results come back in a different shape from the direct fallback. The semantic search branch ignores the document-type filter. The blueprint's projection formula uses the wrong pixel frame. And our pinned OpenAI SDK predates the models we chose. None of this was run: **no code was tested on a headset or against a live Elastic cluster**, so every fix below comes from reading source files and docs, and several need a one-minute check on the day.

*How to read this. "Our code" means files in the Cut Once repo, which I checked locally on 2026-09-19. Everything else comes from five research notes that read the upstream source files directly (GitHub API or raw files) on the same day. Where a note flagged something as a guess or as untested, I say so. Terms: **MRUK** is Meta's Mixed Reality Utility Kit (QR tracking, scene data); **PCA** is Meta's Passthrough Camera API (the Quest's colour camera); **MCP** is the Model Context Protocol, the standard our server uses to call Elastic's Agent Builder tools; **ES|QL** is Elastic's piped query language.*

### A2 Rendering & State: the plumbing is already in the fork; the shader is ours to write

No MIT-licensed, Unity 6-ready "ghost blueprint" shader exists, so `CutOnce/Hologram` should be a URP Unlit Shader Graph (transparent, front faces only, depth write off) with one Custom Function node doing the box-edge, corner-bracket and grid maths from object-space position and object scale. The edge maths in the research notes is our own untested sketch, not taken from any source. Draw SELECTED as a thicker white edge in the same shader rather than adding QuickOutline, which costs two extra passes per object and has an open "won't toggle off on Quest 3 / Unity 6" issue ([issue #46](https://github.com/chrisnolet/QuickOutline/issues/46)). Everything else A2 needs (WebSocket, JSON, HTTP, controller-ray UI) is already in the fork.

Two design ideas come from copyleft code and must be rewritten, not ported. From **Litematica** (LGPL-3.0), take the pure classifier, the nearest-problems list that only re-sorts after the player moves 16 blocks (about 0.25 m for us, so the list doesn't reshuffle while the builder leans), the layer modes (ALL / SINGLE_LAYER / ALL_BELOW / ALL_ABOVE / range, which map onto whole plan / current step / timeline / planned future / steps a..b), and the material-list counts ([SchematicVerifier.java](https://github.com/maruohon/litematica/blob/ornithe/1.12.2/src/main/java/litematica/schematic/verifier/SchematicVerifier.java), [LayerMode.java](https://github.com/maruohon/malilib/blob/ornithe/1.12.2/src/main/java/malilib/config/value/LayerMode.java)). From **Bonsai** (GPL), take only the proportional time formula, frame = start + (t − start) / duration × total frames ([sequence.py](https://github.com/IfcOpenShell/IfcOpenShell/blob/v0.9.0/src/bonsai/bonsai/tool/sequence.py)). ### Rhythm (Copilot, both ends): the fork records audio; everything smart happens on the server

QuestCameraKit's ImageLLM sample is the right starting point for the headset side and the wrong one for the server. It records, transcribes and speaks, but it calls OpenAI straight from the headset with the API key on the device, sends no object ids, uses no structured output, and runs on deprecated models (`gpt-4o`, `whisper-1`, `tts-1`) ([ImageOpenAIConnector.cs](https://github.com/xrdevrob/QuestCameraKit/blob/main/Unity-QuestVisionKit/Assets/Samples/5%20ImageLLM/Scripts/ImageOpenAIConnector.cs)). The best open model for the server is Microsoft's **SIGMA** (MIT), a HoloLens step-guidance copilot. Its prompts fill fixed slots with the task, the current step and what the user said. It grounds objects by asking the model to pick from a supplied list or say "it doesn't belong". And it ships each prompt with regression test cases and a minimum accuracy ([llmqueries.json](https://github.com/microsoft/psi/blob/master/Applications/Sigma/Sigma/Resources/llmqueries.json)). Cut Once can go one step further than SIGMA: build the strict JSON schema per request, with `highlight_parts.items` as an `enum` of this plan's `part_id`s and `drawing_refs[].chunk_id` as an `enum` of the retrieved chunks, so the model *cannot* output an invalid id. That per-request schema should bypass our `toOpenAiSchema(zod)` helper.

### Michael (Platform & Knowledge): official Elastic code covers every tool body we thought was undocumented

Our retriever tree and `copy_to` mapping already match Elastic's own example almost field for field ([retrievers-examples.md](https://github.com/elastic/elasticsearch/blob/main/docs/reference/elasticsearch/rest-apis/retrievers/retrievers-examples.md)), and every ES|QL file in `knowledge/esql/` uses documented syntax. The real gain is on the Agent Builder side. ES|QL in 9.4 has GA `FORK` and `RERANK` (with `FUSE` still in preview), so hybrid search plus reranking can run *inside* one deterministic ES|QL tool, which is a strong showcase for the Elastic prize ([rerank.md](https://github.com/elastic/elasticsearch/blob/main/docs/reference/query-languages/esql/_snippets/commands/layout/rerank.md), [fork.md](https://github.com/elastic/elasticsearch/blob/main/docs/reference/query-languages/esql/_snippets/commands/layout/fork.md)):

```
FROM cutonce-docs METADATA _score
| WHERE MATCH(text, ?query) OR MATCH(text_semantic, ?query)
| SORT _score DESC | LIMIT 30
| RERANK ?query ON text WITH { "inference_id": ".jina-reranker-v3" }
| SORT _score DESC
| KEEP chunk_id, document_id, page, title, text, part_ids, _score
| LIMIT 5
```

No doc example shows `RERANK` taking a named parameter as its query text, so test this once in Discover; if it is rejected, fall back to the retriever-based direct twin. The `OR` also adds a BM25 score to a semantic score on a different scale, which RERANK mostly hides but nobody has measured.

## Conclusion

The comparison shifts where the risk sits. Open source covers the algorithms well: projection, anchors, rigid fitting, audio streaming, hybrid search, prompt structure. What it cannot hand us is the glue, and that is where every Tier 1 bug lives. A sensor-pixel frame is fed to a JPEG-pixel formula. A 2-second timeout races a 120-second default. A tool schema is valid on 9.3 and rejected on 9.4. A pose updates once a second but gets sampled every frame. None of these would show up in a unit test on one side; each shows up only when two systems meet on the demo floor. The practical rule is to call the vendor's function wherever one exists (`WorldToViewportPoint`, `LocalizeAsync(timeout)`, `wait_for_completion`), because every place we re-derived a vendor's behaviour is a place we got it slightly wrong.

The second lesson is about versions. Three of our dependencies sit on a major-version boundary: NativeWebSocket 1 vs 2, openai-node 4 vs 7, and Elastic 9.4 vs 9.5. The right move differs for each: stay on 1.1.6, upgrade to v7, and detect the cluster version before running setup. So the cheapest insurance is one short "versions" check at the start of each owner's next block. In order of payoff, Michael's five Elastic fixes take under an hour and unblock the Elastic prize path. A1's switch to change-only QR sampling alters what gate G3 should measure. Rhythm's projection fix decides whether the copilot's boxes land on the right parts at all.
